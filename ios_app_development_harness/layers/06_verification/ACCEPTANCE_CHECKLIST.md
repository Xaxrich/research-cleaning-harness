# ACCEPTANCE CHECKLIST

Use this checklist before closing a task.

## Scope

- [ ] Task card exists.
- [ ] Active task matches `STATE.md`.
- [ ] Only `allowed_files` changed.
- [ ] `read_only_files` were not edited.
- [ ] `forbidden_files` were not touched.

## Product and Planning

- [ ] Product brief is confirmed when task implements product behavior.
- [ ] Solution plan is confirmed before implementation tasks.
- [ ] Task breakdown is confirmed before multi-task implementation.

## Verification

- [ ] Required verification commands ran.
- [ ] Required verification level was met.
- [ ] Simulator/device evidence exists when required.
- [ ] Failures were recorded in `FAILURE_LOG.md`.

## Review and Trace

- [ ] Review gate was satisfied for high-risk work.
- [ ] Run trace was updated.
- [ ] Retrospective notes were updated when the harness was hard to use.
- [ ] `STATE.md` reflects the next step.
